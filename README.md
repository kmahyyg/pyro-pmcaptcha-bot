## How it works?

1. When a user started private message conversation, user bot retrieved chat id and user id.
2. Ignore any message generated by system, such as auto-delete timer notice.
3. Check if user is a contact, if yes, set redis key `ulist_<CHATID>` to 1, which means allowed user.
4. Check if user is previous passed verification before by checking redis database, if yes, no action taken. 
if not, set `pmstat_<CHATID>` to current timestamp, which means waiting for verification, and set `uinverify_<CHATID>` to verification data, which is comma splited string of session uuid, unix timestamp, remote ip.
send verification message to user, which contains a link to verification page and a generated session uuid in query param `s`.
5. User redirected to verification page hosted on Cloudflare worker, asked to pass Cloudflare Turnstile captcha.
after user finished captcha, worker send turnstile response and remote ip to Turnstile backend to verify result. 
if no error, redirect to result page, generate response in a textarea to allow user for easy copy. Response is a JWK signed with HMAC-SHA-256, signed data is `session UUID + "/" + userID + "/" + timestamp`, `signed data + "/" + signature` is output in base64 without padding.
Ask user to copy and send response back to current chat with: `/verify <RESPONSE DATA HERE>`
6. When user sent verification result, user bot verify signature and check if session uuid and user id match with data in `uinverify_<CHATID>`, 
if not match, send error message and block user. Check with `pmstat_<CHATID>` with response data timestamp, if later than 5 min, expired, send error message and block user. 
Check response timestamp with current timestamp, if later than 45s, expired, send error message and block user.
if match, set `ulist_<CHATID>` to 1, which means allowed user, and delete `pmstat_<CHATID>` and `uinverify_<CHATID>`.

## Redis Schema

```
ulist_<CHATID>: 1   // allowed user
ulist_<CHATID>: 2   // blocked user
pmstat_<CHATID>: curTs  // Wait for Verification, TTL 5min
uinverify_<CHATID>: comma splited data // TTL 5min, verification data: session uuid, unix epoch timestamp, remote ip
```

ErrCode:

- 9001: Already blocked previously
- 9002: Verification Expired within 10min
- 9004: Verification Expired within 95s
- 9003: Signature Verification Failed
- 9099: Database error
- 9098: Python Execution Error

## Docker-compose

Use `bind` mount to mount following file with long syntax in `volumes` key:

- `/app/pmcaptcha_myoungram.session`
- `/app/teleSecrets.py`

Use `attach` subcommand to input authentication data of Telegram.

Use `echo "" > $(docker inspect --format='{{.LogPath}}' <CONTAINER_NAME_OR_ID>)`  to clean logs which logged all your input to prevent sensitive information leakage.

Use `^P + ^Q` to detach from container.
